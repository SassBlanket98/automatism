Seven Jira tickets in. One client update out.

Watch the pipeline read an agency's sprint, keep the internal notes back, write the update, catch its own mistake and hand it to a person to approve. This is a scripted replay on made-up data. The tool isn't built yet.

  1. Collect

    Reads the tickets and comments that changed since the last update, with read-only access to the tracker.

  2. Clean

    Moves internal comments into a store that the draft can learn from but never quote.

  3. Classify

    Sorts each ticket: done, in progress, waiting on the client, a scope question, or internal work to leave out.

  4. Draft

    Writes the update in plain language. Every line carries the ticket it came from.

  5. Guardrails

    Blocks unsourced lines and anything that repeats an internal comment, and flags promises, dates, money and awkward asks.

  6. Review

    A person who knows the project checks the flags and approves. They send it from their own email. The tool can't send.

About this demo

The agency, client, tickets and run are made up, and the replay is the same every time. It shows how the tool is meant to work. The tool hasn't been built yet.
