How the pipeline works

  1. Collect

    Reads the week's GitHub commits, Jira ticket activity, Google Calendar events and existing Harvest entries.

  2. Match

    Uses repos, ticket keys and meeting attendees to find the client and project. Private events stay out. Internal work stays non-billable.

  3. Find gaps

    Compares activity with existing Harvest entries for the same client and project. It finds 4.50 hours without matching entries. The cross-client time check comes later.

  4. Suggest

    Drafts a date, client, project, hours, note and source links for each possible entry.

  5. Guardrails

    Checks the source and existing Harvest entries. A 45 minute overlap on another client is blocked and trimmed, then checked again.

  6. Review

    Sipho checks and approves each corrected entry. The replay shows those approvals one by one.

  7. Log

    Adds only the approved entries to Harvest. Existing entries and invoices are untouched.

About this demo

Northline Studio, Sipho, both clients and all activity are made up. The same scripted run plays every time. It shows the intended workflow; the tool hasn't been built yet.
